# Настройки лимитов CalorieCounterAI

## Что готово

Добавлен серверный маршрут `GET /api/calorie-counter/config`. Он читает пять
переменных окружения сайта и возвращает конфигурацию для мобильного приложения.
Изменения логики мобильного приложения в этот архив не входят: его актуальные
исходники не были приложены. Уже установленные версии приложения сами по себе
не начнут обращаться к новому маршруту после обновления сайта.

## Переменные `.env`

Добавьте эти строки в существующий `.env` сайта, сохранив остальные настройки:

```dotenv
CCAI_FREE_ANALYSES_EXISTING=5
CCAI_FREE_ANALYSES_NEW=5
CCAI_PREMIUM_ANALYSES_EXISTING=50
CCAI_PREMIUM_ANALYSES_NEW=50
CCAI_FIRST_DAY_FREE=false
```

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `CCAI_FREE_ANALYSES_EXISTING` | Бесплатные анализы в день для текущих пользователей | `5` |
| `CCAI_FREE_ANALYSES_NEW` | Бесплатные анализы в день для новых пользователей | `5` |
| `CCAI_PREMIUM_ANALYSES_EXISTING` | Анализы Premium в день для текущих пользователей | `50` |
| `CCAI_PREMIUM_ANALYSES_NEW` | Анализы Premium в день для новых пользователей | `50` |
| `CCAI_FIRST_DAY_FREE` | Бесплатный первый день для новых пользователей без paywall | `false` |

Лимиты принимают целые неотрицательные числа. `0` означает ноль анализов.
Для обеих переменных Premium также разрешено слово `unlimited`:

```dotenv
CCAI_PREMIUM_ANALYSES_EXISTING=unlimited
CCAI_PREMIUM_ANALYSES_NEW=unlimited
CCAI_FIRST_DAY_FREE=true
```

Для последнего параметра используйте `true` или `false` (не `falls`).
Отсутствующее или некорректное значение заменяется значением по умолчанию
только для соответствующего поля. Например, ошибка в одном лимите не сбросит
другие правильно заданные лимиты. Пробелы по краям и регистр `unlimited`/`true`
не влияют на результат. Дробные, отрицательные и слишком большие числа
отклоняются. Для бесплатного лимита `unlimited` не поддерживается.

## Установка на сайт

1. Обновите исходники сайта из архива, сохранив серверный `.env` и загруженные
   пользователями файлы. Готовая `.next` в архив не включена: её необходимо
   собрать на сервере или в обычном процессе сборки сайта.
2. Добавьте пять переменных выше в серверное окружение.
3. Используйте обычный процесс установки зависимостей и сборки сайта
   (`npm ci`, `npm run build`) и перезапустите его серверный процесс.
   Если ваш процесс сборки отдельно генерирует Prisma Client, сохраните этот
   шаг. Этот маршрут не требует миграций базы данных.
4. Проверьте новый URL запросом с действующим `X-Client-Token`.

Для последующих изменений только этих пяти значений достаточно изменить
серверный `.env` и перезапустить процесс сайта, чтобы он перечитал окружение.
Если значения также заданы в настройках хостинга или менеджера процессов,
обновите их там: уже заданные переменные окружения имеют приоритет над `.env`.
Маршрут читает конфигурацию при запросе и возвращает `Cache-Control: no-store`.
Переменные не должны иметь префикс `NEXT_PUBLIC_`.

Механизм загрузки окружения описан в
[документации Next.js](https://nextjs.org/docs/15/app/guides/environment-variables).

## API

После установки маршрут будет доступен по адресу:

```text
GET https://evsi.store/api/calorie-counter/config
X-Client-Token: <тот же токен, который приложение использует для AI-запросов>
```

Пример ответа с настройками по умолчанию:

```json
{
  "schemaVersion": 1,
  "limits": {
    "existingUsers": { "free": 5, "premium": 50 },
    "newUsers": { "free": 5, "premium": 50 }
  },
  "firstDayFreeForNewUsers": false
}
```

В полях `premium` вместо числа может быть строка `"unlimited"`. Она передаётся
явно, без значений `Infinity`, `null` или условного огромного числа.

Сохраняется существующая авторизация CalorieCounterAI: сервер принимает токены
из `CALORIE_COUNTER_CLIENT_TOKENS`, `CALORIE_COUNTER_CLIENT_TOKEN` или
совместимого `SERVER_CLIENT_TOKEN`. Новый отдельный токен не требуется.
Не передавайте токен в адресе запроса.

| Ответ | Значение |
| --- | --- |
| `200` | Конфигурация; незаданные лимиты заполнены значениями 5/50 |
| `403` | Заголовок токена отсутствует или токен неверен |
| `503` | На сервере не настроена существующая авторизация CalorieCounterAI |
| `204` на `OPTIONS` | Ответ на предварительный запрос браузера |

Маршрут возвращает только описанные поля, не раскрывает другие переменные
окружения и не обращается к базе данных или AI. Параметры URL не могут
переопределить серверные настройки. `unlimited` относится к дневной квоте
приложения; существующее техническое ограничение частоты AI-запросов этим
маршрутом не изменяется.

## Оставшаяся интеграция мобильного приложения

Нужен актуальный архив исходников приложения. При интеграции необходимо:

- Загружать и проверять конфигурацию с ограничением времени ожидания. При
  ошибке сети, HTTP, разбора JSON или неизвестной версии схемы использовать
  прежние лимиты 5/50 и выключенный бесплатный первый день. Серверная проверка
  `.env` не заменяет эту защиту на клиенте.
- Определять и сохранять принадлежность пользователя к группе текущих или
  новых, не меняя её при каждом запуске и обновлении приложения.
- Использовать единую конфигурацию в проверке доступности анализа, счётчиках,
  paywall и прочих текстах UI. Числа 5/50 должны остаться только в резервных
  значениях; тексты о лимитах должны получать параметры. `unlimited` требует
  отдельного локализованного текста и обработки в логике счётчика.
- Учитывать бесплатный первый день централизованно во всех точках показа
  paywall и связанных ограничениях. Начало и окончание этого периода нужно
  связать с состоянием нового пользователя, а не со временем каждого запуска.
- Подключить условие видимости кнопки «Оценить приложение»: Premium и новые
  бесплатные пользователи при включённом бесплатном первом дне.
- Локализовать новые строки на все поддерживаемые приложением языки и проверить
  обновление интерфейса после загрузки конфигурации и окончания бесплатного дня.

Эти изменения пока не реализованы в приложении. Этот архив содержит серверную
часть и контракт API для их подключения.

## Проверки

```bash
npm ci
npm run test:calorie-config
```

30 проверок проходят. Они компилируют новый TypeScript-маршрут вместе с
существующим модулем авторизации и проверяют реальные обработчики `GET` и
`OPTIONS`: значения по умолчанию, раздельные квоты, `unlimited`, ноль,
некорректный ввод, флаг первого дня, ответы авторизации, заголовки и повторное
чтение окружения.

Полная production-сборка сайта и проверка развёрнутого URL здесь не выполнены.
Попытка локального запуска Next.js столкнулась с ограничением среды
`uv_resident_set_memory`; HTTP-проверка не завершена. Перед публикацией
проверьте сборку и запрос к маршруту в обычной среде размещения сайта.
